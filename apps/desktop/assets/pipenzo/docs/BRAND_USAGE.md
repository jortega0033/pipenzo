# Pipenzo Brand & Mascot Usage

## Identity hierarchy
1. **Helmet + p mark**: functional identity for app icons, favicon, tiny navigation, installer and system surfaces.
2. **Mini Pipenzo**: decorative/state portrait at roughly 32–96 px.
3. **Detailed Field Engineer**: README, landing pages, onboarding, large empty states, feature illustrations and social compositions.

## Character rules
- The Field Engineer is the canonical Pipenzo identity.
- Commander is operations/orchestration mode, not a second mascot.
- Recon = Refine, Engineer = Implement, Inspector = Review, Auditor = Verify, Ready = awaiting human command.
- Same helmet, goggles, hair silhouette, face, headset, backpack, jacket, boots, p insignia and restrained expression language across roles.
- Refusal is competence, not failure.
- Pipenzo never celebrates before human approval.
- At the final consequential action, Pipenzo waits.
- Do not use a sad mascot to pressure a rejected approval.

## UI restraint
Do not replace semantic warning, approval, security or gate icons with mascot expressions. The mascot supports key moments; it does not replace evidence or status UI. Avoid mascot loading spinners for long-running agent work.

## Palette
The richer khaki/bronze/red character palette belongs to illustrations only. Keep the product UI palette independent and use Pipenzo green as the bridge.

## App icon
Approved direction: monochrome black/white helmet + p. Use the simplified icon for OS surfaces rather than the full mascot head.
