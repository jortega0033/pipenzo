Execution limit One worktree and one branch per running ticket, never shared — issue-94 and issue-97 are two checkouts, not one. {{conc}} / 4
Default 2, hard cap 4. Bounded local concurrency is the honest ceiling for one machine sharing one subscription's rate limit — cloud sandbox fleets are a funded-product feature, not a missing one.
Overlapping tickets are serialised Two tickets whose Refine "files likely touched" lists overlap are held rather than run together. Not configurable — it is what keeps two worktrees from fighting over one file. {{capText}} 1 held
Per-ticket budgets set in the Implement dialog override this. When a budget runs out the ticket parks in Needs human instead of retrying.
Default mode
Which view a ticket opens in Simple shows the outcome and the before/after evidence. Expert shows the activity stream, the gates and the diff.
Simple mode is the default on a new install; your choice is persisted per user. The switch stays in the corner of every ticket either way — this only sets which side it starts on.
Lesson memory local · human-gated One-line notes a person chose to save when a ticket resolved. Handed to the next Refine on that repo as context, never as an instruction, and never sent to a provider. Nothing is ever written here on its own.
